# Правила выпуска и проверки «У Илем 5.0»

Эти правила обязательны для всех последующих изменений проекта.

## 1. Не выдавать документацию за новую сборку игры

- Изменение только README, архитектуры, технического задания, аудита или журнала не является новой версией игры.
- После документационных изменений нельзя сообщать, что игра обновлена, и нельзя выдавать ZIP как новую сборку.
- Ссылку на исходный репозиторий или его ZIP можно дать только с прямой пометкой, что исполняемый код не менялся и это не новая игровая сборка. По умолчанию такую ссылку не прикладывать.

## 2. Когда разрешено выдавать новую сборку

Сборка считается новой только если:
1. Изменены исполняемые файлы игры или ресурсы, влияющие на её поведение/отображение.
2. Изменения опубликованы в каноническом репозитории `pekteevd/U_Ilem_5_0`.
3. Изменённые файлы повторно прочитаны из GitHub после публикации.
4. Проверен diff коммита: видно, какие именно игровые файлы изменились.
5. Проведены доступные автоматические проверки. Проверки, которые невозможно выполнить в текущей среде, прямо перечислены как непроверенные.

## 3. Что сообщать пользователю

Для каждого релиза отдельно указывать:
- что реально изменилось в игре;
- список изменённых исполняемых файлов и ресурсов;
- commit SHA и ссылку на commit;
- результаты проверок и ограничения;
- ZIP только после подтверждения, что в нём содержатся опубликованные изменения.

Не использовать слова «готово», «исправлено», «работает» для функций, которые не запускались и не проверялись. Не подменять проверку факта публикацией кода.

## 4. Канонический проект

- Единственный рабочий репозиторий: `pekteevd/U_Ilem_5_0`.
- Не создавать параллельные репозитории и версии без прямого решения пользователя.
- Утверждённую карту `U_Ilem_5_0_visual_base.png` не заменять и не перерисовывать.
- После существенных изменений кода обновлять ZIP и давать ссылку только после проверки коммита и состава изменений.
- Пользователь не должен вручную собирать архив, если его можно сформировать из репозитория.

## 5. Ошибки, которых нельзя повторять

Нельзя многократно давать ссылку на неизменённый код, создавая впечатление, что это новая сборка. Если код не менялся, нужно сказать это прямо и не называть ссылку обновлением игры.


## Дополнительное правило для переноса интерфейса из старых сборок

При просьбе восстановить интерфейс прошлой версии недостаточно повторить цвета или названия панелей. Перед реализацией необходимо прочитать первоисточник HTML/CSS и восстановить фактическую структуру, пропорции сетки, порядок блоков, соотношение сторон карты, поведение прокрутки и адаптивность. В новой версии переносится компоновка и визуальный язык, но остаются её текущие карта, модель данных, игровые механики и серверные модули. После переноса отдельно проверить, что рабочая область не сжата фиксированной высотой, а сцена карты сохраняет заданное соотношение сторон.
